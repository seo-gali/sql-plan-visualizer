SQLPVI 사용 방법

SQL 파일 준비부터 분석 리포트 열기까지의 순서.

현재 연결: Codex → 로컬 Skill → SQLPVI CLI.

MCP 서버·MCP 등록 설정의 현재 구현 없음. 입력은 .sql 파일, 출력은 HTML·JSON 분석 리포트.

  • 1. 준비
  • 2. 분석 요청
  • 3. 결과 열기
  • 반복 수정
  • 4. DB 계획 추가

STEP 01프로젝트와 SQL 준비

작업 위치: 내려받은 sql-plan-visualizer 프로젝트 폴더.

준비 환경: Python 3.13.15·uv. 처음 사용할 SQL: fixtures/sql/join.sql.

처음 설치의 목적: 정적 분석에 필요한 Core 패키지 준비.

PowerShell · 프로젝트 폴더에서 최초 설치

uv --cache-dir .uv-cache sync --locked --no-dev

이미 필요한 패키지가 설치된 환경은 다음 단계로 이동. 새 설치가 실패한 경우 실제 오류 확인 필요. 기존 환경의 실행 성공과 신규 설치 성공은 별도 항목.

STEP 02Codex 대화에서 분석 요청

Codex에서 이 프로젝트를 열고 로컬 sqlpvi Skill에 요청.

Codex 대화창 · PowerShell 명령과 구분

$sqlpvi
입력: fixtures/sql/join.sql
HTML 출력: artifacts/sqlpvi-join.html

Skill의 처리: CLI 실행 → 종료 결과 확인 → 생성한 HTML 경로 안내.

다른 SQL의 분석: 입력 경로와 출력 경로 교체. 원본과 다른 출력 경로 사용.

SQL 파일 상한: 1MiB. 리포트에 SQL 원문·DB 근거가 포함되므로 공개 전 검토 필요.

PowerShell에서 직접 실행하는 방법

필요한 패키지가 설치된 기존 환경의 명령

uv --cache-dir .uv-cache run --no-sync sqlpvi analyze fixtures/sql/join.sql --output artifacts/sqlpvi-join.html

--no-sync: 설치된 환경 사용. 실패한 새 설치를 복구하는 옵션은 아님.

자동화용 JSON 출력: --format json 추가와 --output artifacts/sqlpvi-join.json 지정.

STEP 03HTML 열기와 결과 확인

성공 결과에서 출력 경로 확인 후 브라우저로 열기.

PowerShell · Windows 기본 앱으로 HTML 열기

Invoke-Item artifacts/sqlpvi-join.html
오해하기 쉬운 표시
PARSEDParser 처리 성공. 실제 DB 실행 가능성·객체 존재 보증 제외.
AMBIGUOUS연결 대상 후보가 여러 개인 상태.
UNRESOLVED연결 대상을 확정할 근거가 부족한 상태.
SQL FlowSQL의 구조와 연산 관계. 실제 DBMS의 물리 실행 순서와 구분.

기존 DB 분석 리포트 예시 열기 →

예시의 기준: 과거 합성 데이터·실제 DB 측정. 방금 생성한 정적 분석의 결과와 별도.

반복 수정: 명령 한 번과 SQL 저장

매번 명령을 다시 입력하는 대신, --watch의 파일 변경 감지 사용.

준비: 분석할 SQL 파일과 기존 설치 환경. 다음 명령의 최초 실행 후 PowerShell 유지.

PowerShell · 현재 실습 파일의 자동 분석 시작

.\.venv\Scripts\sqlpvi.exe analyze artifacts/my-query.sql --output artifacts/my-query.html --watch

문법 오류·파일 부재: 터미널의 오류 표시와 이전 HTML 유지. 수정 저장 후 재분석.

프로그램 코드 갱신 후 Watch 재시작 필요. 저장 감지의 대상은 SQL 파일 내용.

Watch의 범위: 정적 HTML. DB 연결·Query 실행의 자동 반복 없음. --database·JSON 출력과의 결합 거부.

STEP 04필요한 경우의 DB 실행 계획 추가

추가 준비: DB별 Driver Extra·접속 가능한 개발 또는 테스트 DB·조회 전용 계정·접속 URL.

원격 PostgreSQL·MariaDB의 검증된 TLS 요구. SQL Server는 Loopback만 허용. 현재 보안 경계와 미확인 항목 →

기본 파일 분석

analyze 파일.sql

SQL 파일 → 정적 분석 → HTML.

DB 접속 없음.

예상 실행 계획

--database

SQL 파일 → 선택 DB의 예상 계획 조회 → 리포트 추가.

PostgreSQL·MariaDB·SQL Server 지원.

실제 조회 측정

--database --runtime

SQL 파일 → 조회 Query 실행·측정 → 리포트 추가.

PostgreSQL만 지원. 실제 실행에 대한 명시적 요청 필요.

PostgreSQL 예상 계획의 실행 예

전제: 저장소의 격리 PostgreSQL 준비와 조회 전용 Fixture 계정의 사용.

PowerShell · PostgreSQL Driver 설치와 연결 설정

uv --cache-dir .uv-cache sync --locked --no-dev --extra postgres
$env:SQLPVI_POSTGRES_URL = 'postgresql://sqlpvi_reader@127.0.0.1:55432/sqlpvi'
uv --cache-dir .uv-cache run --no-sync sqlpvi analyze fixtures/sql/join.sql --database --output artifacts/sqlpvi-join-plan.html

결과의 추가 영역: Execution Plan·확보된 Database Metadata.

현재 설치·Fixture가 준비된 경우의 예제. 이 안내 작성 중 실제 DB 명령의 실행 없음.

기본 Skill의 범위: 정적 파일 분석. DB 실행 요청의 자동 확대 없음.

추천 SQL·Index·Schema의 자동 변경 없음. 개선 후보는 충분한 실측 근거 확보 시에만 표시.
