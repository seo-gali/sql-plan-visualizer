3. 코드 개선 3건의 정확한 범위

3-1. 출력 폴더 자동 생성

문제: 결과를 넣을 폴더가 없으면 HTML·JSON 저장 실패. 변경: 분석과 보고서 생성 성공 뒤 부모 폴더 생성.

src/sqlpvi/cli.py의 실제 추가 코드:

output.parent.mkdir(parents=True, exist_ok=True)
output.write_text(result, encoding="utf-8")

이미 존재하는 폴더의 유지. SQL 입력 파일과 같은 파일로의 출력 거부 유지. Hardlink로 같은 파일을 가리키는 경우도 거부. 잘못된 SQL은 새 출력 폴더를 만들기 전에 실패.

검사: HTML·JSON의 중첩 폴더 생성, 부모 위치가 폴더가 아닌 파일일 때 원문 보존, 잘못된 SQL의 폴더 미생성, 기존 Hardlink 보호.

3-2. SQL Server Table Hint 일부 허용

Hint는 SQL에 붙이는 특별 지시. 이전에는 종류와 무관하게 전부 차단. 현재는 인자 없는 아래 네 이름만 허용.

허용 이름뜻과 적용 범위
NOLOCK, READUNCOMMITTED읽는 방법에 관한 지시. 실제 조회에서 일관된 결과·잠금 부재를 보장하는 이름이 아님. SQLPVI의 SQL Server 모드에서는 조회 실행 없이 계획만 수집.
FORCESEEK, FORCESCAN인덱스 접근 경로에 관한 지시. 원문에 이미 있을 때 계획 수집 허용. SQLPVI가 새로 삽입하는 지시가 아님.

UPDLOCK·HOLDLOCK·XLOCK·TABLOCKX 등 잠금 강제 Hint의 차단 유지. 모르는 Hint와 INDEX(...) 같은 인자 있는 형태도 차단. 허용 Hint에 금지 Hint를 섞은 경우 거부.

변경 지점: src/sqlpvi/db/safety.py. SQL Server의 SHOWPLAN_XML 경계 유지. 쓰기 허용 옵션 추가 없음.

검사: 드라이버를 부르기 전 금지 SQL 거부, 허용 Hint의 SHOWPLAN 전달, 실제 SQL Server에서 허용 네 종류의 예상 계획 수집과 Actual Rows 없음 확인.

3-3. PostgreSQL 해시 임시 파일 점검 추가

해시는 자료를 묶어 서로 맞춰 보는 작업의 한 방법. 메모리만으로 처리하기 어려우면 일을 나누고 임시 파일을 사용할 수 있음. 현재 추천은 기존 정렬 점검과 새 해시 점검의 두 종류.

검사 조건정확한 내용

새 해시 후보Hash 노드, Hash Batches>1, 양수 Temp Written Blocks·Actual Rows·Loops.
불충분한 값누락·0·음수·문자열·Bool·NaN·Infinity의 근거 사용 금지.
결과의 뜻“입력량과 세션 메모리 점검” 후보. 성능 문제 확정, 인덱스 생성, 전역 메모리 증설의 자동 결정 없음.
DB 영향이미 수집한 계획을 읽는 순수 함수. 추천을 만들기 위한 추가 DB 접속·SQL 실행 없음. 제안 SQL은 보고서의 텍스트.

변경 지점: src/sqlpvi/recommend.py, 한국어 표시의 src/sqlpvi/assets/report.js. 시험 SQL: fixtures/sql/hash-spill.sql.

실제 생성 결과: 실측 해시 추천 보고서. 이 실행의 관측값은 Hash Batches=8, Temp Written Blocks=31, Actual Rows=10000, Loops=1. 모든 환경의 고정 정답값으로 사용하지 않는 수치.

실제 시험: 해당 테스트 세션에서만 work_mem 64kB·8MB 비교와 Merge/Nested Loop Join 비활성화. 앞의 조건에서 해시 후보 생성, 뒤에서 미생성. 제품이 DB 설정을 자동 변경하는 기능 추가 없음.

4. DB 준비를 반복 요청한 이유와 실제 영향

DockSlate 앱은 컨테이너를 관리하는 화면. 컨테이너는 DB 서버를 담은 실행 상자. 앱 실행만으로 해당 상자 세 개의 실행이 보장되는 것은 아님.

대상현재 분석용 포트준비 이유
PostgreSQL127.0.0.1:55432예상 계획·Catalog·실제 측정·정렬/해시 추천의 검사
MariaDB127.0.0.1:53306EXPLAIN JSON 변환·계정 권한·회귀 검사
새 SQL Server, mssql127.0.0.1:14330SHOWPLAN XML·Hint·권한·Timeout·연결 복구 검사
옛 SQL Server, sqlserver이전 설정 51433삭제 없이 기존 DB 보존. 현재 분석 연결 대상으로 사용하지 않음. 사용자의 마지막 화면에서는 실행 중.

안내했던 명령의 목적

docker compose up -d --wait postgres mariadb mssql
docker compose run --rm sqlserver-init

첫 줄: compose.yaml의 DB 세 서비스를 준비하고 정상 상태까지 대기. 없는 이미지 다운로드·컨테이너 생성 가능. 기존 DB 데이터 삭제·초기화 명령은 아님.

둘째 줄: SQL Server의 시험용 DB·표·계정이 없으면 생성. 시험용 계정의 GRANT 권한 부여 재적용 가능. “모든 경우 읽기만 하는 명령”은 아님. --rm은 작업을 수행한 일회성 init 컨테이너 정리이며, DB 서버·Volume 삭제 옵션은 아님.

예전 컨테이너 삭제를 피하기 위해 --remove-orphans 사용 안내 없음. 예약 포트 회피 과정에서 Windows 전역 포트 설정 변경 없음.

실제 DB 검사에 포함된 동작

대상은 loopback에 묶인 합성 자료의 격리 시험 DB. 운영 DB 연결 작업 없음. 공개 시험용 암호와 조회 전용 계정 사용.

보호 확인용 시험에는 거부되어야 할 UPDATE 시도와 잠금 Timeout을 재현하기 위한 일시적 ALTER TABLE 트랜잭션도 포함. 해당 잠금 시험은 finally의 Rollback. 실측 전후 orders 행 수·합계·public Index 정의의 동일성 검사 통과.

반복이 길어진 이유: 셸의 DockSlate 실행 제한, 컨테이너 내부 정상 여부와 호스트 포트 문제의 분리, 처음 사용한 포트의 Windows 예약 충돌. Health 확인만으로 호스트 연결이 가능하다고 판단할 수 없었음.

5. uv 명령의 뜻과 영향 범위

uv는 Python 실행 환경과 필요한 부품을 관리하는 도구. 이번 명령은 DB 조회 명령이 아니라, 프로젝트 실행에 필요한 패키지를 설치·확인하는 명령.

uv --cache-dir artifacts/uv-cache sync --locked --link-mode copy
부분쉬운 뜻정확한 영향
uvPython 부품 관리 도구 실행명령을 실행한 프로젝트의 설정을 찾는 동작
--cache-dir artifacts/uv-cache부품을 받아 두는 별도 창고 선택현재 작업 위치를 기준으로 한 상대 경로. 문제가 난 옛 .uv-cache를 삭제하는 옵션이 아님.
sync프로젝트가 정한 부품 목록에 환경을 맞추기.venv 패키지 설치·교체·목록에 없는 패키지 제거 가능. 설치 상태를 바꿀 수 있는 명령.
--locked정해 둔 버전 목록의 변경 방지Lock 갱신이 필요하면 실패. 설치 자체를 읽기 전용으로 만드는 옵션은 아님.
--link-mode copy캐시 파일과 연결하는 대신 파일 복사파일 공유 방식의 선택. Windows 권한을 높이거나 해제하는 옵션이 아님. 기존 캐시를 이용한 복사 방식 빌드도 실제 실패했으므로, 이 옵션만으로 해결을 보장할 수 없음.

왜 다른 프로젝트에서 실행된 결과가 생겼나

첫 안내에 --directory 또는 명시적인 폴더 이동이 없었음. 따라서 사용자의 현재 PowerShell 위치가 실행 대상을 결정. 제가 이 점을 처음부터 명시하지 않은 것이 문제.

의도한 위치

...\Agent\sql-plan-visualizer

SQLPVI의 pyproject·Lock·가상환경을 대상으로 실행. 현재 Lock 해석 결과 16 packages.

사용자가 올린 실제 위치

...\Agent\boiler-ops-agent

그 프로젝트에서 실행. 사용자 출력은 24 packages / Checked 22 packages. SQLPVI 설치 검증 근거로 사용 불가.

이후 안내한 수정 명령은 대상 폴더를 먼저 선택하는 --directory 포함. 아래는 수정 안내의 기록. SQLPVI에서 실행됐다는 결과는 아직 없음.

uv --directory D:/01_Programming/08_AI/Agent/sql-plan-visualizer --cache-dir artifacts/uv-cache sync --locked --link-mode copy

명령에서 DB 주소·SQL·파일 삭제·권한 변경·전역 설정 변경 지정 없음. 다만 해당 프로젝트의 가상환경을 맞추는 설치 명령이므로, 영향 범위를 “아무것도 바꾸지 않음”으로 설명하면 부정확.
