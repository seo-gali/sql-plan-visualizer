STEP 01발견한 문제와 수정

생성 리포트의 Git 제외

기본 출력 *.sqlpvi.html의 제외 추가. 사용자 지정 HTML·JSON은 공개 전 개별 검토 필요.

부품·보안 유지 절차

기존 추적 파일의 삭제·이동, 운영 계정 변경, DB 초기화, 키의 외부 전송·회전 미수행.

STEP 03Secret 검사와 노출 범위

초기 작업 파일 100개, 19일 최종 작업 파일 104개와 로컬 Git의 4개 커밋·104개 고유 Blob 검사. 비밀값·원문·키 Hash를 결과에 출력하지 않는 방식.

검사 대상: 개인키 헤더·AWS/GitHub/OpenAI/Anthropic/Google/Slack/Stripe 키 패턴·DB URL 암호·문자열 Secret 할당.

환경 파일: .env.example만 존재. 프로젝트 접속 URL Key 4개의 빈 값 확인. 현재 프로세스에 SQLPVI 접속 URL 없음.

환경 범위: 프로세스 91항목, 사용자 지속 환경 3항목, 시스템 지속 환경 23항목의 프로젝트 관련 설정 검토. 현재 도구의 전역 인증값과 다른 실행 중인 셸의 환경은 앱 설정과 구분.

확인된 값: 공개 SQL Server Fixture 암호와 오류 마스킹 시험값. 실제 계정·운영 환경에서 사용하지 않는 합성 테스트 값.

검사의 한계: 자체 패턴 검사. 미지의 Secret 형식·바이너리·원격의 미수신 커밋·도달 불가능 객체·다른 셸 환경 전체의 무유출 보증 제외. 실제 키 유효성의 외부 확인 없음.

Compose의 개발 전용 설정 유지.

PostgreSQL Trust·MariaDB 무비밀번호 Root·공개 SQL Server 암호는 Loopback 합성 Fixture용. 운영·외부 배포용 인증으로 사용 금지. 이번에 DB·계정·Volume 변경 없음.

STEP 04의존성 조회의 실제 범위

Lock의 외부 패키지 15개와 빌드 도구 setuptools의 버전별 PyPI JSON 조회 시도. 현재 확인 가능한 13개 응답의 vulnerabilities 목록은 비어 있음.

등록 취약점 목록이 비어 있는 상태와 전체 안전 판정의 구분. OSV 요청 실패와 3개 응답 미확인으로 전체 자동 취약점 감사는 미완료.

STEP 06출시 전 남은 확인

1. 실제 DB·TLS 통합 확인. 현재 보강한 PostgreSQL 권한 SQL과 원격 인증서 정책의 실제 서버 검증 필요.

2. 의존성 전체 감사. 실패한 OSV 조회와 미확인 3개 버전, Runtime·네이티브 라이브러리·이미지 검사 필요.

3. 운영 인증·호스팅. Fixture 설정의 운영 재사용 금지. Pages의 HTTPS 강제·응답 보안 헤더·보안 알림 설정 확인 필요.

19일 읽기 시도: Pages API와 공개 사이트의 응답을 이 웹 도구에서 가져오지 못함. HTTPS 강제 설정의 확인·변경 완료로 기록하지 않은 상태.

호환성 변화. 1MiB 초과 SQL과 원격 SQL Server의 거부. 원격 PostgreSQL·MariaDB에 신뢰 가능한 인증서 요구.

Secret 검사 한계. 실제 유출 키의 미탐지를 무유출 확정으로 해석하지 않는 기준. 키 폐기·교체·Git 히스토리 재작성 없음.
